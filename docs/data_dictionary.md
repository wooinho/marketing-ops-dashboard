## 2. 테이블 정의

### revenue_target_actual_monthly.csv → `revenue_monthly`
그룹(전체/1그룹/2그룹) × 월(1~12) 단위 매출/매입/매출이익 목표·실적.

| 컬럼 | 설명 |
|---|---|
| group → grp | `전체` \| `1그룹` \| `2그룹` |
| month | 1~12 |
| revenue_target / cost_target / profit_target | 해당 월의 목표(연간 목표를 월별로 배분한 값) |
| revenue_actual / cost_actual / profit_actual | 해당 월의 실적(스냅샷 B). 그룹의 실적 반영 기간을 넘는 월은 `NULL` |
| has_actual | 1=실적 반영, 0=목표만 존재 |

**실적 반영 기간**: 1그룹 1~11월, 2그룹 1~10월. 이 범위를 벗어나는 달은 원본 시트에 매출/매입이
0으로 표시되어 있어도(그리고 일부 달은 매출이익 셀에 30,000,000~100,000,000원 등 **평탄한(flat) 값이
남아있어도**) 실적이 아니라 목표/추정치 잔여값으로 판단해 `NULL`로 처리했습니다.
(자세한 근거는 4번 항목 "매출이익 플랫값" 참고)

### revenue_group_annual.csv → `revenue_group_annual`
그룹 단위 연간 목표/실적/달성률(스냅샷 B의 `26' 목표` / `26' Total` / `달성율` 컬럼).
`cost_rate_pct`는 원본 시트에 매입 달성률이 정의되어 있지 않아 항상 `NULL`입니다(매입은 적을수록 좋으므로 달성률 개념이 없음).

### revenue_client_annual.csv → `revenue_client_annual`
광고주별 연간 목표/실적/달성률(스냅샷 B). `client_raw`는 원본 표기, `client`는 정규화된 명칭
(`config/client_name_mapping.csv` 참고). `quality_flag` 값:

- `REF_ERROR` — 목표 셀이 `#REF!`(참조 깨짐). 광고주 "타이거"만 해당.
- `DIV0_NO_TARGET` — 목표가 비어 있어 달성률이 `#DIV/0!`. "신규 광고주" 슬롯들(목표 미확정, 실적도 0).
- `TARGET_ONLY_NO_ACTUAL` — 목표는 있으나 실적이 아직 0(스나이델뷰티).

### revenue_client_monthly.csv → `revenue_client_monthly`
광고주별 월간 매출/매입/매출이익(스냅샷 B). 1그룹은 1~11월, 2그룹은 1~10월만 값이 있습니다
(그 외 월은 로드 시점에 CSV 자체에 행이 없음 = 해당 안 됨).

### resource_mm_group1.csv / resource_mm_group2.csv
1·2그룹 리소스 현황 시트의 "그룹합계"(1그룹) / "브랜드별 합계"(2그룹) 행을 월별로 그대로 옮긴 표입니다.
파생 계산 없이 원본 값을 그대로 실었으며, `note` 컬럼에 해당 셀의 특이사항을 기록했습니다.

### staff_mm_group1.csv / staff_mm_group2.csv
담당자별 월간 MM 투입(근사치 포함). `basis` 컬럼이 `원본 월간값`이면 시트에 월 단위로 이미 집계된
값을 그대로 사용한 것이고, `주차값 평균 근사`/`주차 서술값 근사(파일럿)`이면 주차별 기록만 있는 달을
평균으로 근사한 것입니다(아래 "MM 근사 방식" 참고).

### staff_roles_group1.csv / staff_roles_group2.csv
담당자 × 클라이언트 × (월 또는 스냅샷) → 역할(PM/S.AE/AE) 매트릭스.
2그룹 시트는 각 표에 월 라벨이 명확히 붙어 있지 않아 `snapshot`(1=최신 ~ 5=과거) 순번으로 기록했습니다.

## 3. 광고주명 정규화 매핑

전체 매핑은 `config/client_name_mapping.csv` 참고. 핵심 판단:

- "매일유업 앱솔루트 산양" → `매일유업_산양`, "매일유업 셀렉스 썬화이버" → `매일유업_셀렉스` (하나의
  "매일유업"으로 합치지 않고 서브라인 단위 유지 — 매출 트래킹 시트가 이미 서브라인 단위로 목표를 관리함).
- "젤라또 피케"(공백 포함 원본) → `젤라또피케`(공백 제거, 리소스 시트 표기와 통일).
- 1그룹 리소스/담당자 시트의 **"키린"** 은 매출 트래킹 시트에는 존재하지 않는 이름이지만, 월별 매출액이
  `Qeelin`과 정확히 일치(예: 7월 599,895원)하여 **동일 광고주의 내부 별칭(코드명)** 으로 판단해 매핑했습니다.
  (판단 근거: 우연히 여러 달에 걸쳐 두 자릿수까지 일치하는 숫자가 반복되는 것은 별칭일 가능성이 매핑 오류일
  가능성보다 훨씬 높다고 보았습니다.)
- 2그룹 리소스 시트의 퓨리나 5개 서브라인(프로플랜/ONE/프리스키/자사몰/SNS)은 매출 트래킹 시트에서는
  `네슬레_퓨리나` 하나로 통합 집계되어 있어, 매출/수익 대시보드에서는 통합값을 쓰고 MM 페이지에서만
  서브라인 구분을 유지했습니다.
- "핀코퍼레이션"과 "AYROW"는 스냅샷 A(구버전) 또는 파이프라인성 항목에서만 등장하고 스냅샷 B(정본)의
  광고주별 실적 표에는 없어 매출/매출이익 실적 집계에서 **제외**했습니다(데이터 격차로 문서화).

## 4. 데이터 품질 이슈 전체 목록

1. **스냅샷 A vs B** — 위 1번 항목. B를 정본으로 사용.
2. **`#DIV/0!`** (원본에 약 238회 등장) — 매출이 0인 매입 전용 행 등에서 발생. 오류가 아니라 "계산 불가"로
   간주해 `NULL`(대시보드에는 N/A)로 처리했습니다.
3. **`#REF!`** — 광고주 "타이거"의 매입/매출이익 **목표** 셀에서만 발생(참조가 깨진 셀). 목표를 `NULL`
   처리했고 실적도 0으로 기록되어 있어 `REF_ERROR` 플래그를 달았습니다. (구버전 목표관리 표에서도
   동일 오류가 나타나지만 그 표는 애초에 사용하지 않습니다.)
4. **음수 표기 두 가지** — `-₩1,234`와 `(1,234)` 형태가 모두 등장. `src/ingestion.clean_currency()`가 둘
   다 음수로 정상 변환합니다.
5. **통화 문자열 형태 혼재** — `"₩84,563,690"`처럼 원화 기호+쉼표가 붙은 문자열과 `84563690`처럼 순수
   숫자가 같은 표 안에 혼재. `clean_currency()`가 `₩`/쉼표/공백을 제거한 뒤 숫자로 변환합니다.
6. **매출이익 "플랫(flat)" 값** — 여러 광고주(예: 한화생명 8~12월, 풀무원요거트그릭 8~12월 등)의
   매출이익 컬럼이 특정 시점 이후 매달 정확히 같은 금액(예: 30,000,000원, 8,000,000원)으로 반복됩니다.
   매출/매입은 그 달 실제 값이 들어있는데 매출이익만 평탄한 것으로 보아, **원본 시트의 매출이익 수식이
   그 시점 이후 갱신되지 않고 이전 추정치가 복사되어 남아있는 것으로 추정**합니다. 그룹의 실적 반영
   기간(1그룹 11월까지/2그룹 10월까지) 안쪽 달은 원본 값을 그대로 실었고, 범위를 벗어난 달은 `NULL`
   처리했습니다. 정확한 매출이익 재계산은 원본 시트 소유자 확인이 필요합니다.
7. **2그룹 8월 리소스 그룹합계 공백** — `1그룹 프로젝트 리소스 현황`과 달리 `2그룹 프로젝트 리소스 현황`의
   8월 섹션은 매출/매입/수익/생산성 총계 셀이 원본에서 비어 있고, MM 투입량만 브랜드별로 기록되어
   있습니다. `resource_mm_group2.csv`의 8월 행은 `revenue/cost/profit/productivity_per_mm`이 모두
   `NULL`이며 `note`에 이 사실을 남겼습니다.
8. **2그룹 6월 MM 총계 불일치** — 원본에 "6월 MM(크리렙 제외)" 총계가 서로 다른 위치에 2.9와 6.1로
   따로 기록되어 있습니다. 브랜드별 세부값의 합은 약 5.0입니다. 임의로 한쪽을 정답 처리하지 않고
   docs에 병기했습니다(대시보드에는 브랜드별 세부값만 표시).
9. **1그룹 6월 MM 총계 불일치** — 담당자별 MM 합계는 약 7.1인데, 원본의 "MM(크리렙제외) 합계" 셀은
   13.4로 기록되어 다른 산식(예: 중복 포함)을 사용한 것으로 보입니다. 두 수치를 모두 남겨두었습니다.
10. **노임단가(labor rate) 레거시 변경** — 2그룹 리소스 시트에서 3~4월과 5~8월 사이 레벨별 월 노임
    단가 기준이 달라집니다(예: 리더 1,000만원→1,500만원, 매니저 800만원→1,200만원). 두 기준을 병합하지
    않고 각 시점 그대로 두었습니다. BEP/생산성을 월 간 비교할 때 이 점을 감안해야 합니다.
11. **담당자별 월간 MM 근사치** — 원본이 주차별로만 기록된 달(1그룹 7·8월, 2그룹 7·8월)은 주차값을
    단순 합산하면 월 4~5주치가 그대로 더해져 실제보다 4~5배 과대산정됩니다. 이 대시보드는 **주차값의
    평균**을 월간 MM 근사치로 사용했습니다(다른 달의 "이미 월 단위로 집계된" 값과 스케일을 맞추기 위함).
    `staff_mm_group*.csv`의 `basis` 컬럼에 근사 여부를 표시했습니다.
12. **1그룹 리소스 시트의 "키린" = Qeelin 별칭** — 3번 항목 참고.
13. **핀코퍼레이션 / AYROW 스냅샷 B 누락** — 3번 항목 참고. 실적 집계에서 제외, 문서에만 기록.
14. **3월 2그룹 매출 컬럼 중복 의심** — 사용자 제공 요약에 "매일유업 17,000,000 + 17,000,000(중복 풀무원
    카드)"라는 언급이 있어 원본 자체에 열 중복/오프셋 가능성이 있습니다. `resource_mm_group2.csv`의
    3월 행 `note`에 "일부 컬럼 중복 표기 가능성, 원본 확인 필요"로 남기고 재검산하지 않았습니다.
15. **CJ문화재단 등 소액 클라이언트의 생산성 음수** — MM이 작을 때 생산성(수익/MM)이 부호가 뒤집히거나
    극단값이 나오는 경우가 있습니다(예: 2그룹 7월 CJ문화재단 생산성 -1,634,094원). 계산 오류가 아니라
    "분모가 작을 때 비율 지표가 불안정하다"는 일반적 현상이며, MM 생산성 페이지가 파일럿으로 표시된
    이유 중 하나입니다.
16. **월별 목표 매입 달성률 없음** — 스냅샷 B에 매입(비용) 항목은 목표는 있지만 "달성율" 컬럼이 항상
    비어 있습니다. 매입은 적게 쓸수록 좋으므로 매출/매출이익과 같은 의미의 달성률 개념이 없다고 보고
    `cost_rate_pct`를 모든 레벨에서 `NULL`로 유지했습니다.
    (단, 이는 그룹 단위 요약(`revenue_group_annual.csv`)에만 해당합니다. 광고주별 표(`revenue_client_annual.csv`)에는
    원본 시트에 매입 달성율 셀이 실제로 채워져 있어 그대로 가져왔습니다.)
17. **[2026-09-17 갱신에서 신규 발견] 스나이델뷰티가 광고주별 실적 표에서 사라짐** — 이전 세션에서는
    "2그룹\_광고주별" 표(스냅샷 A/B 둘 다)에 스나이델뷰티 행이 있었으나(목표만 있고 실적 0,
    `TARGET_ONLY_NO_ACTUAL`), 이번에 재추출한 원본 시트에는 스냅샷 A/B 어느 쪽에도 스나이델뷰티
    행이 더 이상 존재하지 않습니다. 다만 "마캠본부 목표 관리" 표에는 여전히 스나이델뷰티 목표
    (매출 16,800,000 / 매입 15,120,000 / 매출이익 1,680,000, 월 1,400,000/1,260,000/140,000 균등 배분)가
    남아있습니다. 광고주별 실적 집계 자체가 사라진 것인지, 시트 정리 과정에서 행이 삭제된 것인지는
    원본 시트 소유자 확인이 필요합니다. 이 대시보드는 목표 관리 표의 값을 사용해 기존과 동일하게
    목표만 있고 실적 0인 `TARGET_ONLY_NO_ACTUAL` 행을 유지했습니다(`revenue_client_annual.csv`).
